# IMAGE ACQUISITION GUIDE — S South Coorg Security Services (SSCSS)

> **How to legally and efficiently source every image the site needs.** Use this with `IMAGE_PRIORITY.md` (what to shoot first), `IMAGE_SHOTLIST.md` (exactly what to shoot), and `IMAGE_REUSE_MATRIX.md` (the consolidated library). Following the licensing/model/property release checklists here prevents the most common — and most expensive — problems later.

---

## 1. Where to source images (ranked)

### Priority 1 — Your own photography (SSCSS personnel, sites, equipment)
**Always the best choice.** Real guards, real uniforms, real Bengaluru sites = maximum trust and zero brand mismatch.
- **Effort:** one scheduling + 1–2 shoot days.
- **Cost:** staff time + modest equipment; a photographer only if budget allows (see below).
- **Covers:** heroes, service shots, gallery, founder, clients, certificates (scans).
- **Controls:** full ownership, unlimited reuse, no license expiry.
- **Tip:** shoot at 3–4 representative client sites (corporate, industrial/gate, residential community, hospital/school) so one day covers ~70–80% of still needs (`IMAGE_REUSE_MATRIX.md`).

### Priority 2 — Professional photographer
Best for hero and founder imagery where polish matters and for guaranteed consistency of light/tone.
- **Handler:** brief them with `IMAGE_SHOTLIST.md` prompts + `IMAGE_STRATEGY.md` style section (documentary/premium, natural light, de-saturated grade, deep-red accent restraint).
- **Contract:** assign full usage rights (commercial web, social, GBP, print) and confirm the photographer won't resell to a competitor.
- **Coverage:** full shoot-day plan from `IMAGE_REUSE_MATRIX.md` (masters M-01…M-27).

### Priority 3 — Premium licensed stock (Adobe Stock / Shutterstock)
Acceptable **interim fill** for scenes you cannot shoot (rare), provided it matches the style guide. Use the `IMAGE_SHOTLIST.md` prompts as exact search briefs.
- Prefer authentic Indian/Bengaluru corporate, industrial, logistical scenes with a documentary feel.
- **Only** use extended-license/all-rights works for web use; set `isPlaceholder=false` only when the license covers commercial web publication.
- Stock should be a bridge, not the destination — always plan to replace with real SSCSS footage.

### Priority 4 — Free sources (use with caution)
- **Unsplash:** only if a specific image genuinely fits (realistic, Indian context, no model-fake). Free but model/property rights rest with the uploader — risk if it turns out to be a real person/brand without consent.
- **Pexels:** limited suitability (often "generic guard" or western settings). Only as last-resort texture, never as a trust-critical hero.

### Priority 5 — NEVER use (computers/tablets blocked list)
See **"What NOT to use"** below.

## 2. What NOT to use

| Red flag | Why it hurts |
|----------|--------------|
| **AI-generated / AI-looking imagery** | Reads inauthentic; becomes a credibility liability for an enterprise brand. Design.md forbids it. |
| **Generic "smiling guard" stock** | Fake, indistinguishable, low-trust; clashes with "Disciplined" positioning. |
| **Fake handshake stock photos** | Over-used, clichéd, reads as stock instantly — damages premium credibility. |
| **Over-edited HDR images** | Harsh, digital, "budget" look; violates the documentary/premium grade. |
| **Cartoon illustrations / mascots** | Forbidden by design.md; childish, not enterprise. |
| **Images with visible watermarks** | Unprofessional and legally risky; never publish. |
| **Western/out-of-context scenes** | A European office or US mall doesn't reflect Bengaluru reality. |
| **Clients'/brand logos without permission** | Legal risk — only show logos where `permissionConfirmed === true`. |
| **Unlicensed person photos (real faces)** | Personal-data/privacy risk in India (IT/DPDP considerations) — needs model release. |

## 3. Licensing checklist

Run this for **every** sourced image (stock or commissioned), and log the result.

- [ ] Identify the exact license type (Royalty-Free / Rights-Managed / Extended / All-Rights / custom).
- [ ] Confirm **commercial web + social + GBP use** is permitted (many free/RF tiers restrict).
- [ ] Confirm can be **modified/cropped** (some RF forbid derivative edits or require attribution).
- [ ] Confirm **no on-site watermark/invisible watermark**.
- [ ] Confirm **model & property releases** exist on file (for stock with identifiable people/property).
- [ ] Check license does **not expire** (RF) or note expiry date (RM) and set a reminder.
- [ ] Record **invoice/license ID** and store a copy of the license PDF beside the asset.
- [ ] If using for **og:image / schema.org**, confirm social/meta use is within license scope.
- [ ] Never publish with `isPlaceholder=false` until license verified.
- [ ] Keep a **source spreadsheet**: filename, source, license type, license ID, expiry, release status, alt, caption.

---

## 4. Model release checklist

Applies to **any identifiable person** in owned/shoot photography (SSCSS personnel count — even staff need consent for public web use).

- [ ] Written model release (or work-for-hire/policy note for employees) explaining the images will appear **publicly online** (website), social media, and Google Business Profile.
- [ ] For SSCSS guards/staff: get signed individual consent; note whether uniforms/badges include any client-brand (separate property concern).
- [ ] For **clients' sites/people**: written consent from the client organization **and** any identifiable individuals (visitors, staff, patients — especially sensitive for hospitals/schools).
- [ ] Minors (school events) — parental/guardian consent; prefer not to feature minors.
- [ ] Note any **exclusivity** (person shouldn't also appear as a rival agency's guard).
- [ ] Store signed releases securely with the asset record.
- [ ] For stock: confirm the provider's own model release already covers the image (Adobe/Shutterstock indicate this) — don't re-derive.

---

## 5. Property release checklist

Applies whenever a **private/identifiable location** (client office lobby, warehouse, residential community) is photographed.

- [ ] Written permission from the property owner/occupier (client organization) to photograph and publish the premises.
- [ ] If the site is a **client's** facility, keep goodwill: share intended shots and clearly scope where photos will appear.
- [ ] Avoid photographing **confidential/sensitive** areas: server rooms, control-room screens with data, cash/ATM interiors, restricted industrial areas, people's faces at medical/school settings.
- [ ] For **residential properties**, permission from the apartment association and avoid unit interiors.
- [ ] For **government/HERITAGE** premises, check public-photography rules — restrict if uncertain.
- [ ] Log each location's property release with the asset record.
- [ ] For stock: rely on provider property-release flags; prefer stock that is marked "property released."

---

## 6. Brand consistency checklist (applies every shoot/source)

- [ ] **Uniforms:** identical, immaculate, consistent cut — never mixed/worn styles. Confirm current SSCSS uniform spec.
- [ ] **Brand color:** deep-red accent only as detail (lanyard, badge, signage); navy/base neutral for uniforms.
- [ ] **Tone:** documentary/premium; natural light; de-saturated grade; no HDR/cartoon/AI gloss.
- [ ] **Composition:** follow `IMAGE_STRATEGY.md` (negative space, leading lines, subject right-of-center for heroes).
- [ ] **Aspect ratios:** capture masters at high-res with margins so heroes (3:2/4:3), portraits (4:5), cards, and gallery tiles can all be cropped from one file.
- [ ] **Logo/branding in-frame:** confirm any visible signage/logos are accurate, current, and not a competitor's.
- [ ] **Consistency of people:** same look of guards across gallery and heroes (don't mix a smart team shot with a scruffy one).
- [ ] **Metadata:** add IPTC/EXIF copyright "© S South Coorg Security Services" and location tags.
- [ ] **Versioning:** save with `vN` suffix so re-shoots don't break cache/alt/schema references (`IMAGE_SEO_GUIDE.md`).
- [ ] **Accessibility:** keep alt/schema accurate from day one; decorative images `aria-hidden`.

## 7. Recommended shoot-day plan (from the reuse matrix)

| Session | Location(s) | Masters | Deliverables |
|---------|-------------|---------|--------------|
| **Session 1 — Operations** | 3–4 client sites (corporate, residential, industrial/gate, hospital/school/hotel) | M-01…M-16, M-20, M-22, M-24(stills) | Heroes, service shots, gallery stills, card thumbs |
| **Session 1B — Video** | Same sites | M-01…M-16 (V), M-23, M-25, M-26 | Patrol, check-in, fire drill, corporate walkthrough, IFMS team loop |
| **Session 2 — People+Studio** | Office / studio / founder home/office | M-17 (founder), dressing-room detail | Founder portrait, close-up equipment, professional headshots |
| **Documents** | Office | M-18 (scans) | Clean straight-on PSARA/GST/PF/ESI scans |
| **Brand/Logos** | Client (permitted) | M-20 (logo wall) | Client logo files (permission-gated) |

> **Budgeting note:** Prioritize **Session 1 + Session 2 stills + documents** first (cover `IMAGE_PRIORITY.md` Phase 1–2). Add video (Session 1B) as Phase 3 budget allows — it materially lifts the hero and gallery but is not launch-blocking.

## 8. Handoff

- Drop final WebP/AVIF exports into the correct `public/images/...` folder.
- Flip the matching `ImageRef.isPlaceholder` to `false` in the content files (data-only per `schema.md` §9) and update `alt`.
- Update `IMAGE_SEO_GUIDE.md` schema/og:image references and the source-spreadsheet release status.
- Schedule a periodic re-check (license expiries, logo permissions, uniform changes).
